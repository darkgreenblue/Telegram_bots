# پشتیبانی — دفترِ تیکت‌ها (منبع حقیقتِ سابقه‌ی پشتیبانی)

سشنِ «پشتیبانیِ ربات‌ها» هر پیامِ کاربر را این‌جا ثبت می‌کند تا سابقه‌ی هر کاربر، تصمیمِ ما و
پیامی که فرستادیم برای همیشه بماند و در تیکتِ بعدیِ همان کاربر خوانده شود.

## چرا فایل، نه جدول در دیتابیسِ ربات
- سشنِ کلاد به سرور SSH ندارد؛ تنها راهِ نوشتنِ ماندگار، کامیت روی ریپوست (بند ۳ ریشه).
- دیتابیسِ ربات مقدس است (بند ۹/۲ج): تیکتِ پشتیبانی داده‌ی عملیاتیِ ماست، نه دیتای محصول،
  و نباید در مسیرِ نوشتنِ رباتِ زنده بنشیند.
- JSONL در گیت diff‌پذیر و merge‌پذیر است و با یک کوئری به SQLite بارگذاری می‌شود
  (`tools/support-log.mjs sqlite`), پس «دیتابیس بودن» را از دست نمی‌دهیم.
- `support/` زیرِ `bots/` نیست، پس تغییرش **هیچ رباتی را ری‌استارت نمی‌کند** (بند ۳).

## فایل‌ها
- `tickets.jsonl` — append-only، هر خط یک تیکت (schema پایین).
- `tools/support-log.mjs` — افزودن/جستجو/نمایش + خروجی SQLite.

## Schema (نسخه‌ی ۱)
| فیلد | معنا |
|------|------|
| `id` | `T-YYYYMMDD-NN` (تهران) |
| `ts` / `date` | لحظه‌ی ثبت (unix) و تاریخِ خواناى تهران |
| `bot` | کلیدِ ربات (`tarot`, `voice2text`, …) |
| `support_code` | کدِ پیگیری `#TRT-<uid>` (اگر کاربر داده باشد) |
| `user_id` | آی‌دیِ عددی تلگرام (مرجعِ هویت) |
| `user_message` | متنِ پیامِ کاربر (خلاصه‌شده اگر خیلی بلند بود) |
| `category` | `payment` / `credit` / `reading` / `bug` / `question` / `feature` / `other` |
| `verdict` | `confirmed_bug` / `partial` / `user_error` / `no_issue` / `info` / `pending` |
| `findings` | چیزی که در دیتا دیدیم (با عدد، نه حدس) |
| `actions` | کارهایی که کردیم (فیکس، شارژ جبرانی، ثبت باگ) |
| `reply` | پیامی که برای کاربر تنظیم شد |
| `bug_ref` | لینکِ Issue/PR اگر باگ بود |
| `status` | `answered` / `awaiting_user` / `in_progress` / `closed` |

## قواعد
1. **هر تیکت ثبت می‌شود**، حتی وقتی مشکلی نبوده (`no_issue`) — الگوها فقط از روی همه‌ی تیکت‌ها دیده می‌شوند.
2. قبل از جواب دادن، سابقه‌ی همان کاربر خوانده می‌شود: `node tools/support-log.mjs user <uid>`.
3. اگر باگ تأیید شد، `verdict=confirmed_bug` و `bug_ref` اجباری است؛ فیکس در همان سشن شروع می‌شود.
4. پیامِ کاربر خلاصه/ویرایش نشود مگر برای طول؛ متنِ خام ارزشِ تحلیلی دارد.
