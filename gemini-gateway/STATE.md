# gemini-gateway — وضعیت و تصمیم‌ها

> تک‌منبعِ پیشرفتِ این پروژه. هر سشنِ Claude Code یا Codex که روی آن کار می‌کند اول این فایل
> را کامل می‌خواند و در پایانِ کار به‌روزش می‌کند. آخرین به‌روزرسانی: ۱۴۰۵/۰۷/۰۸.

## هدف

سرویسی که تولیدِ **عکس و ویدیو** را از **سایتِ جمنای** (`gemini.google.com`، اشتراکِ Google AI
Pro) مثل یک **API با مستنداتِ خودکار** در اختیار می‌گذارد، بدون اینکه کسی چت‌بات را باز کند.

- **مصرف‌کننده‌ی اول:** سیستمِ اتوماسیونِ کاملِ تبلیغاتِ تلگرام (کشفِ کانال/ربات → انگلِ
  تبلیغاتی → پوستر/ویدیو → کمپین‌های متعدد در ads.telegram.org → بهینه‌سازی با CPA).
  طراحیِ آن سیستم پروژه‌ی جداست و بعد از این دروازه شروع می‌شود.
- **مغزِ فعلی:** Claude Code یا Codex (هر دو باید بتوانند). مالک در یک سشن می‌گوید «فلان
  پوستر/ویدیو را می‌خواهم» یا «برای فلان محصول تبلیغ کن» و سشن در صورتِ نیاز دروازه را صدا
  می‌زند.
- **محصولِ رو-به-کاربر:** فعلاً **نه**. معماری فقط باید مثل «API + مستندات» قابلِ وصل‌شدن
  باشد؛ فکرِ پشتیبان/مقیاس برای محصول **عمداً** به بعد موکول شده (تصمیمِ صریحِ مالک).

| موضوع | تصمیم |

| Google Flow | رد شد (دردسرِ مرورگر). فقط خودِ چت‌باتِ جمنای |

| ریسکِ حساب | مالک **صریحاً پذیرفته**؛ در عوض همه‌ی تمهیداتِ کاهشِ اثرانگشت اجباری است |
| حساب‌ها | **چند حساب Pro به‌عنوانِ فالبکِ هم** در معماری از روزِ اول؛ شروع با یک حساب، بعد ۲–۳ حسابِ دیگر |

| خاموش/روشن | «کارگر» (بخشِ وصل به گوگل) با اولین درخواستِ یک **کار** روشن، با دستورِ صریحِ «پایانِ کار» از Claude/Codex خاموش؛ **۳۰ دقیقه بی‌درخواستی = خاموشیِ خودکار** به‌عنوانِ تورِ ایمنی. «پذیرش» (API) همیشه‌روشن است و با گوگل تماسی ندارد |
| ساعتِ کار | محدودیتِ ساعتی ندارد؛ مالک خودش در زمان‌های طبیعی فعال می‌کند |
| مرورگرِ برداشتنِ کوکی | Firefox Developer Edition (مالک دارد) |
| جای پروژه | همین پوشه، کاملاً مجزا از `bots/` |
| کنترل | از داخلِ Claude Code/Codex (نه رباتِ تلگرامِ جدا)؛ هشدارها به تلگرامِ مالک |

| Codex | CLI روی لپ‌تاپِ مالک با دسترسیِ بیشتر؛ همکار در کارهای لپ‌تاپ‌محور (مثلاً برداشتن/به‌روزکردنِ کوکی از Firefox و `gh secret set`). رهبری با Claude Code |

## معماری (به‌روز: ابزار = ورک‌فلو، ۱۴۰۵/۰۷/۰۸)

```
Claude Code / Codex
      │ workflow_dispatch (GitHub MCP / gh) با ورودیِ JSONِ درخواست‌های یک «کار»
      ▼
رانرِ GitHub Actions = یک جلسه‌ی کار
  ├─ Xray با نودِ چسبیده‌ی همان حساب از اشتراکِ V2Ray (گوگل IPِ نود را می‌بیند، نه IPِ متغیرِ رانر)
  ├─ بازکردنِ وضعیتِ رمزشده (کوکیِ چرخیده، نودِ چسبیده، سهمیه، قفلِ ترمز per حساب)
  ├─ هسته‌ی دروازه: مسیریابِ حساب‌ها (۱ ← ۲ ← ۳)، صفِ یکی‌یکی، مکث‌های نامنظم
  ├─ خروجی: فایل‌ها به‌صورتِ artifact + خلاصه‌ی JSON در لاگ
  └─ ذخیره‌ی دوباره‌ی وضعیتِ رمزشده، پایانِ جاب = خاموشی
```

- **هسته مستقل از ترابری است:** همان کتابخانه‌ی داخلی بعداً بدونِ تغییر پشتِ یک سرورِ HTTP
  (با مستنداتِ خودکار) می‌نشیند اگر محصولی لازمش داشت. قراردادِ درخواست/پاسخ از روزِ اول
  یک اسکیمای JSONِ مستند است.
- **دقیقه‌ی Actions** هزینه‌ی اصلی است (بند ۳ج ریشه): وابستگی‌ها و باینریِ Xray کش می‌شوند و
  همه‌ی درخواست‌های یک کار در **یک** اجرا می‌روند.
- ⚠️ وقتی ریپو موقتاً public است لاگ و artifact عمومی‌اند: کوکی/وضعیت هرگز چاپ نمی‌شود؛
  برای خروجیِ حساس الگوی رمزکردن با کلیدِ عمومیِ per سشن (`db-query-sealed`) آماده است.

## تمهیداتِ اثرانگشت (از خواندنِ کدِ مرجع، نسخه‌ی 2.1.1)

| مشاهده در کدِ مرجع | تصمیمِ ما |
|---|---|
| همیشه خودش را `chrome145` معرفی می‌کند (`constants.py`) ولی README کوکی از Firefox را توصیه می‌کند | هویتِ یکدست: مرورگری که کوکی از آن برداشته می‌شود = هویتِ معرفی‌شده = هدرها. ⚠️ اینکه لایه‌ی زیرین (curl-cffi) هویتِ Firefox را پشتیبانی کند **هنوز تأیید نشده** |
| `start_activity_watchdog`: هر ۶۰–۱۲۰ ثانیه، ۲۴ ساعته، درخواستِ «فعالیت» | فقط داخلِ جلسه‌ی کار؛ بیرونِ جلسه سکوتِ کامل |
| هر `init` چند درخواستِ پشت‌سرهم (صفحه، توکن، مدل‌ها، سهمیه) | واحدِ روشن/خاموش «کار» است نه «درخواست» |
| کوکیِ چرخیده باید قبل از خاموشی ذخیره شود (باگش در 2.1.1 رفع شده) | ذخیره‌ی اتمیک (فایلِ موقت + rename) بعد از هر چرخش و قبل از خاموشی |

به‌علاوه:
- **هر حساب به یک نود می‌چسبد**؛ مرگِ نود ← اول نودِ همان کشور، تغییرِ کشور فقط با هشدار.
- **لاگین/برداشتنِ کوکی از پشتِ همان نود** (Karing روی نودی که دروازه برای آن حساب گزارش می‌کند).
- صفِ واحد، مکث‌های نامنظم، سقفِ روزانه زیرِ سهمیه، پرامپت‌های غیرقالبی، و **نسخه‌های یک
  پوستر در یک گفتگو** (اصلاحِ پشت‌سرهم مثلِ یک طراح).
- **ترمزِ اضطراری per حساب:** پیامِ سقف/«ترافیکِ غیرعادی»/خطای احرازِ هویت ← قفلِ همان حساب،
  صفر تلاشِ دوباره، هشدار به تلگرامِ مالک.
- ⛔ **مرز:** توکن‌های امنیتیِ گوگل (BotGuard/`x-browser-validation`) جعل نمی‌شوند و کپچا
  با سرویسِ واسطه حل نمی‌شود.

تلگرامِ مالک، با لاگِ کامل. نتیجه‌اش تعیین می‌کند مسیرِ عکس برای حسابِ مالک باز است یا نه (#344).
