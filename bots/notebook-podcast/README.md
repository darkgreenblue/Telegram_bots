# Telegram → NotebookLM Studio

ربات شخصی مالک برای ساخت نوت‌بوک از چند منبع و دریافت خروجی‌های NotebookLM در تلگرام.

## پادکست خودکار دیلی بریف

زمان‌بند همین سرویس هر روز ساعت ۰۶:۰۰ به وقت تهران، دیتابیس «جلسه‌ها» در Learning Roadmap را با فیلد «تاریخ» جست‌وجو می‌کند. تمام متن جلسهٔ همان روز، شامل جدول‌ها و بخش‌های تودرتو، یک منبع متنی در نوت‌بوک تازه می‌شود. پادکست با زبان فارسی، قالب گفت‌وگوی عمیق و طول «بلند» ساخته می‌شود؛ پرامپت جداگانه خالی است. فایل در همین ربات `@DAILY_BRIEFF_bot` با کپشن «محتوای آموزشی امروز صبح! تاریخ: ...» از ساعت ۰۶:۳۰ به بعد ارسال می‌شود. اگر تا ۰۶:۳۰ صفحه‌ای با آن تاریخ نباشد، پیام «امروز محتوای آموزشی نداریم!» ارسال می‌شود. در خطای دسترسی به Notion یا ساخت پادکست، پیام خطا می‌رود و تلاش دوباره به‌صورت خودکار انجام می‌شود. هر روز یک درخواست با وضعیت پایدار در SQLite دارد تا ری‌استارت سرویس درخواست تازهٔ تکراری نسازد. این مسیر از OpenRouter استفاده نمی‌کند.

توکن `DAILY_BRIEF_NOTION_TOKEN` که از قبل در GitHub تنظیم شده است، در استقرار این سرویس نیز لازم است. Integration نوشن باید به Learning Roadmap و دیتابیس جلسه‌ها دسترسی داشته باشد. زمان‌بندی پروژهٔ قدیمی Daily Brief روی VPS خاموش است؛ این کد آن را روشن نمی‌کند.

## رفتار ربات

۱. «📥 ورود ورودی‌ها» را بزنید و نام نوت‌بوک را بدهید. همان نام در NotebookLM ثبت می‌شود. در هر لحظه فقط یک مجموعه در حال دریافت ورودی است، اما تا سه درخواست می‌توانند هم‌زمان در مراحل بعدی باز باشند.
۲. متن، لینک وب یا یوتیوب، PDF، فایل متنی، Word، PowerPoint، EPUB، CSV، تصویر، صوت یا ویدیو بفرستید. فایل‌ها به NotebookLM سپرده می‌شوند و اگر نوعی را نپذیرد، پس از زدن دکمهٔ پایان خطا گزارش می‌شود. در مرحلهٔ جمع‌آوری ربات عمداً هیچ پاسخی به هر ورودی نمی‌دهد.
۳. «✅ ورودی‌ها تمام شد» را بزنید. ربات یک نوت‌بوک تازه می‌سازد و منابع را به ترتیب وارد می‌کند. اگر منبعی رد شود، تولید خروجی شروع نمی‌شود.
۴. نوع خروجی را انتخاب کنید: پادکست، ویدیو، ویدیوی سینمایی، اسلاید PDF یا PowerPoint، اینفوگرافیک، گزارش، جدول داده، آزمون، فلش‌کارت یا نقشهٔ ذهنی. زبان، گزینه‌های ویژهٔ آن خروجی و پرامپت راهنما قابل انتخاب‌اند.
۵. فایل خروجی در همان چت ارسال می‌شود. همهٔ پادکست‌ها، چه روزانه و چه دستی، پس از دانلود روی سرور با `ffmpeg` به MP3 تک‌کاناله با نرخ ۹۶ کیلوبیت‌برثانیه تبدیل می‌شوند و با مدت‌زمان پخش به تلگرام فرستاده می‌شوند. از «📚 نوت‌بوک‌های من» می‌توان نوت‌بوک‌های ساخته‌شده با همین ربات را دوباره انتخاب و با منابع قبلی خروجی تازه تولید کرد. برای متن پرامپت یا کد زبان، روی پیام تنظیمات همان مجموعه Reply بزنید تا درخواست‌ها جابه‌جا نشوند.

تنها شناسه‌های عددی در `OWNER_TELEGRAM_ID` اجازهٔ استفاده دارند. درخواست‌ها و فهرست نوت‌بوک‌های ساخته‌شده با ربات در SQLite زیر `data/` حفظ می‌شوند. فایل‌های موقت پس از آپلود یا تحویل پاک می‌شوند. نوت‌بوک و منابع واردشده در حساب گوگل باقی می‌مانند. فایل‌های بزرگ‌تر از ۵۰ مگابایت با لینک نوت‌بوک تحویل داده می‌شوند.

## Secrets در GitHub

در ریپوی `darkgreenblue/Telegram_bots` به `Settings → Secrets and variables → Actions → New repository secret` بروید:

| نام دقیق | مقدار |
|---|---|
| `NOTEBOOK_PODCAST_BOT_TOKEN` | توکن همین ربات از BotFather |
| `NOTEBOOK_PODCAST_GOOGLE_MASTER_TOKEN_JSON` | **متن کامل** فایل `master_token.json` که در مرحلهٔ بعد ساخته می‌شود |
| `NOTEBOOK_PODCAST_PROXY_CONFIG_JSON` | کانفیگ محرمانهٔ Xray شامل نودهای اشتراک؛ فقط در Secret نگهداری شود |
| `DAILY_BRIEF_NOTION_TOKEN` | توکن Integration با دسترسی خواندن رودمپ و جلسه‌ها |
| `OWNER_TELEGRAM_ID` | شناسهٔ عددی تلگرام مالک؛ این Secret احتمالاً از قبل در ریپو تنظیم شده است |
| `VPS_SSH_KEY` | کلید اتصال VPS؛ از قبل در ریپو تنظیم شده و نباید عوض شود |

هیچ‌کدام را در چت، کد، Issue یا Pull Request قرار ندهید. اشتراک Google AI Pro خودش کلید API نیست؛ ربات از نشست همان حساب در NotebookLM استفاده می‌کند.

### ساخت فایل ورود گوگل

روی **کامپیوتر شخصیِ قابل‌اعتماد**، با Python 3.10 یا جدیدتر و مرورگر گرافیکی:

```bash
python3 -m venv notebook-login-venv
./notebook-login-venv/bin/pip install 'notebooklm-py[headless,browser]==0.8.3'
./notebook-login-venv/bin/notebooklm -p notebook-podcast login --master-token --account YOUR_GOOGLE_EMAIL
```

در پنجرهٔ مرورگری که باز می‌شود، با حسابِ دارای دسترسی NotebookLM وارد شوید. سپس محتوای فایل `~/.notebooklm/profiles/notebook-podcast/master_token.json` را **فقط** به‌عنوان مقدار Secret بالا در GitHub قرار دهید. این فایل دسترسی گسترده و ماندگار به حساب گوگل می‌دهد؛ بهتر است از یک حساب جداگانه با دسترسی لازم استفاده شود. فایل را در ریپو کپی نکنید. راهنمای رسمی کتابخانه: [headless server installation](https://github.com/teng-lin/notebooklm-py/blob/main/docs/installation.md#d-headless-server-or-ci).

## استقرار و بررسی

Workflow مستقل `Deploy Notebook Podcast` روی تغییرات این پوشه در `main` اجرا می‌شود. اگر سکرتی هنوز وارد نشده باشد، استقرار را رد می‌کند و نام سکرت‌های لازم را در لاگ می‌نویسد. پس از واردکردن سکرت‌ها، از تب `Actions → Deploy Notebook Podcast → Run workflow` آن را دستی اجرا کنید. کاربر نیازی به SSH ندارد. Workflow فقط پروسه‌های PM2 همین ربات (`notebook-podcast` و `notebook-podcast-proxy`) را reload می‌کند.

پیش از هر مرحلهٔ پردازش، ربات نودهای موجود در Secret را به‌صورت واقعی با تلگرام و NotebookLM می‌سنجد و سریع‌ترین نود سالم را برای همان کار انتخاب می‌کند. سه کار در سه فرایند و سه پورت محلی مستقل اجرا می‌شوند؛ انتخاب نود یک کار، مسیر دو کار دیگر را تغییر نمی‌دهد. ترافیک بقیهٔ VPS از این پراکسی عبور نمی‌کند. این انتخاب از نسخهٔ فعلی کانفیگ انجام می‌شود؛ اگر اشتراک نودهای تازه بدهد یا رمزها تغییر کنند، باید Secret به‌روز و workflow دوباره اجرا شود. اگر همهٔ نودها قطع باشند یا NotebookLM خودش خطا بدهد، درخواست با داده‌های ذخیره‌شده به حالت تلاش دوباره می‌رود.

برای آزمون واقعی، به ربات `/start` بفرستید و یک متن کوتاه و یک لینک یوتیوبِ دارای زیرنویس را امتحان کنید. ورود لینک یوتیوب فقط رونوشت آن را به منبع تبدیل می‌کند. ربات با API معمولی تلگرام نمی‌تواند فایل ورودی بزرگ‌تر از ۲۰ مگابایت را دانلود کند یا صوت بزرگ‌تر از ۵۰ مگابایت را مستقیم بفرستد.

## اجرای محلی توسعه

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
# BOT_TOKEN و ADMIN_IDS را فقط در .env محلی وارد کنید.
.venv/bin/python bot.py
```

برای آزمون‌های بدون شبکه: `.venv/bin/python -m unittest discover -p 'test_*.py'`.
