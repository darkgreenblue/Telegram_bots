# resume-tailor

ربات تلگرام: اول با گرفتن «شرح کامل سوابق کاری» + «رزومه‌ی اصلی» تو رو می‌شناسه، بعد برای هر آگهی شغلی (لینک یا متن) یک **رزومه‌ی استاندارد انگلیسیِ کاستومایز** می‌سازه.

- اجرا: Node ۲۰، long-polling، دیتابیس SQLite در `./data/bot.db`

## تخصیص مدل (بهینه‌ی هزینه — همه از OpenRouter)
`gemini-2.5-pro` فقط برای **یک** درخواست در هر رزومه استفاده می‌شود (بخش Experience که بزرگ‌ترین/مهم‌ترین بخش است). بقیه با `gemini-2.5-flash`:

| مرحله | مدل |
|------|-----|
| ویس→متن، استخراج تماس | Flash |
| ساماندهی پروفایل (لایه۱ و لایه۲) و ویرایش | Flash |
| مغزِ ساختار (تعیین بخش‌ها) | Flash |
| تولید رزومه — Experience | **Pro** |
| تولید رزومه — Summary، Skills و هر بخش دیگر | Flash |

## فلو (چندایجنتی)
1. `/start` → «رزومه داری؟» (دکمه دارم/ندارم). اگر داری، آخرین نسخه (حتی ناقص) را می‌فرستی → ذخیره به‌عنوان رزومه‌ی اصلی.
2. **جمع‌آوریِ چندفایلی سوابق**: هر تعداد فایل/پیام/ویس را دانه‌دانه می‌فرستی؛ هرکدام تأیید می‌شود و دکمه‌ی «✅ همه را فرستادم» پایان‌بخش است. پردازش فقط بعد از این دکمه شروع می‌شود.
3. **ساماندهیِ چندایجنتی (Gemini Pro)**: لایه۱ شرکت‌ها را تفکیک می‌کند، لایه۲ هر شرکت را ساختارمند می‌کند (عناوین/کارها/مهارت‌ها/تغییرات تاریخ‌دار/اثر). خروجی: «پروفایل ساختاریافته».
4. `/profile` نمایش پروفایل · `/edit` ویرایش هر شرکت با **متن یا ویس** (ویس→متن با Gemini 2.5 Flash).
5. برای هر آگهی: لینک (کرال؛ در صورت شکست، متن دستی) → توضیحات تکمیلی اختیاری → **تولید چندایجنتی** → خروجی متن + فایل `.md`.
   - ابتدا یک **ایجنت مغزِ ساختار (Flash)** تصمیم می‌گیرد رزومه شامل چه بخش‌هایی باشد (بر اساس آگهی + رزومه‌ی قبلی + پروفایل + خواسته‌ی کاربر + دانش رزومه‌نویسی). همیشه Summary/Skills/Experience هست؛ بخش‌های دیگر (Projects/Education/Certifications/...) فقط در صورت پشتیبانی داده یا درخواست کاربر.
   - سپس هر بخش با **ایجنت اختصاصیِ خودش** و به‌صورت موازی ساخته و در ترتیبِ تعیین‌شده ترکیب می‌شود.

دستورها: `/profile`, `/edit`, `/cancel`, `/reset`, `/help`

> **اصل ضدتوهم:** همه‌ی ایجنت‌ها فقط از داده‌های واقعیِ کاربر استفاده می‌کنند و چیزی نمی‌سازند.
> **هوک Deep Research:** ثابتِ `RESUME_KNOWLEDGE` در `index.js` محل تزریق «نکات کلیدیِ تحقیق رزومه‌نویسی» است که به همه‌ی ایجنت‌های تولید می‌رود (فعلاً مبنای استاندارد؛ با رسیدن فایل کاربر تکمیل می‌شود).

## اجرای محلی
```bash
cp .env.example .env   # BOT_TOKEN و OPENROUTER_API_KEY این پروژه را بگذارید
npm install
npm start
```

## دیپلوی روی VPS
این ربات بخشی از مونوریپوست و با PM2 از طریق `ecosystem.config.cjs` ریشه اجرا می‌شود.
نیازی به SSH دستی نیست؛ توکن و کلید **جداگانه** (برای اندازه‌گیری هزینه) از طریق GitHub Secrets تزریق می‌شوند:

در GitHub: **Settings → Secrets and variables → Actions → New repository secret** و این دو را بسازید:
- `RESUME_TAILOR_BOT_TOKEN` = توکن تلگرام این ربات
- `RESUME_TAILOR_OPENROUTER_KEY` = کلید OpenRouter این ربات

workflowِ `Deploy` در هر push به `main`، فایل `bots/resume-tailor/.env` را روی سرور از روی همین secretها می‌سازد و ربات را با pm2 استارت می‌کند. تا وقتی این دو secret تنظیم نشده باشند، ربات به‌صورت امن skip می‌شود و `voice2text` دست‌نخورده می‌ماند.
